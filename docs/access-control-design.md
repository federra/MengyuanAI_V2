# 账号授权与管理员后台：精简开发方案

日期：2026-09-15。状态：第一阶段中央基础已实现并部署；第二阶段桌面登录与门禁源码及隔离测试已完成，第三阶段管理员后台源码、联调与中央接口部署已完成，第四阶段统计采集、持久化补传、隔离联调和中央部署已完成。统计实施见 [第四阶段记录](access-control-usage.md)。后台实施见 [第三阶段记录](access-control-admin.md)。桌面实施见 [第二阶段记录](access-control-desktop.md)。部署事实见 [部署手册](access-control-deployment.md)。

本稿按用户要求：**满足当前系统要求，保留适当迭代余量，不提前建设无需求的平台能力。**本稿取代上一版方案。UI 见 [原型说明](prototypes/access-admin/README.md)，审阅记录见 [需求审阅](access-control-review.md)。

## 一、范围与规则

### 1、用户已确认的要求

- 三类产品身份：路人、普通会员、超级管理员。路人仅见登录与必要状态提示，不见任何业务界面；普通会员以账号＋密钥登录，在有效期内且未封禁即可使用全部业务功能；超管另有管理后台。
- 新增登录页和管理员后台两类页面。后台入口放在“系统设置”下方，仅超管可见；普通会员即使直接访问后台地址或接口也不能进入。
- 超管可新增普通会员、设定账号/密钥/使用期限、封禁/恢复、查看每个用户当天和历史使用情况、查看全部普通会员的数据汇总、查询自己的操作日志。**不可删除用户记录**。
- 每次管理员操作留痕。普通会员保留现有创作、收益/渠道账本、模型设置等全部业务功能；这些功能操作自身数据，不因此获得平台用户管理权限。
- 当日指标包括创意、故事、剧本、素材、导出视频等。用户补充确认：**导出视频数统计系统成功导出的视频文件，区分分镜视频与最终成片**。
- 保留现有浅色、深色主题。不新增充值、订单、卡密兑换、自助注册、分档套餐、积分、代理权限系统、运营/财务角色或设备额度限制。

### 2、必要状态规则

数据库只存 `member` 和 `super_admin` 两种角色；“路人”是没有有效业务授权的访问状态，无需额外建游客表。会员到期不删除用户、不覆盖其历史身份；有效条件为：账号存在、凭据正确、未封禁、服务端当前时间早于到期时间。超管无需会员到期时间。

封禁与到期独立：封禁不暂停授权计时，恢复只解除封禁、不自动延期，延期也不自动解封。新建立即生效；授权表单提供具体到期时间和从现在起 7/30/90/365 天快捷设置。后台可缩短或延长期限。时间存 UTC，显示和输入为北京时间，精确到分钟；到达指定分钟即失效。

**技术建议不等于用户已确认的额外限制：**中央服务运行环境、心跳频率、会话期限和密钥长度是实现默认值，可调整。首期采用联网校验便于封禁生效；不另开发离线授权体系。无需新增永久会员选项，也不把“禁止永久会员”写成用户要求。

## 二、页面与 Demo

### 1、页面设计

复用当前 `app/globals.css`、`app/dark-theme.css` 的蓝色按钮、浅/深色面板、Segoe UI / Microsoft YaHei 字体、216px 侧栏、圆角和现有图标，不重做整套工作台。

| 页面/区域 | 首期内容 |
|---|---|
| 登录 | 品牌、账号、密钥（默认隐藏，可显示）、登录按钮、未授权请联系管理员；错误凭据、已到期、已封禁、连接失败提示；登录前不加载项目或显示菜单 |
| 登录后 | 会员和超管均进入原工作台；超管从侧栏进入后台，也能返回全部原业务页面；退出后回到登录 |
| 数据概览 | 今日/历史累计五项指标、近 7 日创意趋势、会员状态数量、用户使用明细；不包含超管活动 |
| 用户管理 | 账号/备注搜索、有效/到期/封禁筛选；新增用户、调整期限、封禁/恢复、使用详情；无删除入口、无旧密钥查看入口 |
| 用户详情 | 当天/累计、自选日期范围、五项指标、事件明细与分页；新用户全部为零且无历史记录 |
| 操作日志 | 时间、操作者、对象、动作、前后变化、原因、结果；按对象/操作者、动作和日期查询，分页，只读 |

用户变更填写操作原因并确认；普通查询自动记录查询条件，不要求填写原因。表单键入不属于已提交操作，不记录密钥或创作正文。登录先验证凭据再显示到期/封禁原因；账号或密钥错误统一提示。

### 2、Demo 边界

原型在 `docs/prototypes/access-admin/`，独立 HTML/CSS/JS，仅虚构数据，不连接正式服务。默认地址从登录开始，没有身份切换器；只有 `?review=1` 开启评审场景切换。单独 `?view=admin` 不能跳过登录。评审工具永不进入正式版本。

新增模拟用户后，可以退出并用刚设定的账号与密钥登录。封禁、到期、恢复、延期共用同一份模拟状态。页面刷新清除所有模拟修改。大盘、趋势和用户详情从同一组事件求和，不使用彼此无关的占位数字；超管样例事件明确排除。原业务页面只保留已授权占位，不在 Demo 里重复实现。

## 三、最小可用技术架构

### 1、部署与存储

**一套中央账号服务＋现有 Web/桌面客户端。**中央保存账号、会话、统计和日志；桌面继续保存作品、素材、模型配置及豆包账号。登录不意味着作品自动跨设备同步。

建议中央服务放在现有自有服务器，使用 Node.js / TypeScript＋SQLite＋Nginx HTTPS，单实例即可；当前服务器已有更新发布用途，但不能据此认为账号服务已存在。复用现有部署入口前先检查环境、持久盘和备份，保持软件更新路径可用。暂不引入 Redis、微服务、多租户平台或数据库切换层。

中央仅需四张表：

| 表 | 必要字段 |
|---|---|
| users | id、唯一规范化账号、备注名、role、key_hash、expires_at、banned_at、ban_reason、revision、created_at、updated_at |
| sessions | 不透明 token 的摘要、user_id、创建/到期/撤销时间、client_type；退出/封禁时撤销；不保存登录密钥 |
| usage_events | 唯一 event_id、user_id、role_at_event、operation_id、output_id、metric、video_kind（shot/final）、quantity、occurred_at、received_at、source；按用户/日期索引 |
| admin_audit_logs | id、request_id、操作者、目标、动作、前后值、原因、结果、服务端时间；按时间/对象索引 |

首期直接对有索引的 usage_events 聚合，**不先建日报表、统计缓存或独立幂等请求表**。事件唯一键处理重传；需要优化时再增加汇总表。金额、订单、套餐和权限矩阵均不建表。

账号规范化建议为去首尾空格、转小写、3–64 位字母数字和 `._-`，唯一；密钥区分大小写、不自动修剪，推荐 12–128 位，随机生成使用至少 16 个随机字节。正式服务用带盐的密码摘要保存，不能可逆读取。密码摘要选型参照 [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。初始化超管使用部署时保密输入，不预置在安装包、Git或命令行参数中；普通新增用户表单不提供提权。

### 2、认证与授权边界

`登录表单 → 当前端会话桥 → 中央验证 → 返回身份 → 加载工作台`

- Web 增加同源 `/api/auth/*`，使用 HttpOnly/Secure/SameSite 会话 Cookie；业务 API 从可信会话解析 user_id。保留现有同源保护。访问后台时服务端检查 super_admin，默认拒绝未授权请求，参照 [OWASP Authorization](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)。
- 桌面主进程保存中央会话（内存）；原 `director_session` 仍只负责本机访问保护。Node 后端宿主与主进程通过现有 IPC 通信，Worker 通过受控桥查询授权；不能在 Worker 中直接调用 Node 的 process.send。
- 登录前不挂载原工作台、不拉取项目。中央会话推荐 12 小时到期，本期不另外增加闲置踢出、设备数或并发登录限制。应用启动先展示登录；同一进程刷新可在线验证后恢复。
- 每个业务 API 和敏感 IPC 在执行前校验账号状态；超管写操作必须在线校验。前端/桌面可用约 15 秒心跳更新空闲界面，恢复焦点立即检查。这是推荐频率，不承诺物理意义上的即时推送。
- 封禁、到期或退出后隐藏业务并阻止新操作；断网阻止新操作且提示连接失败，不能把网络故障显示成封禁。到期按服务端时间判断，不能通过修改本地时间延长。
- 未保存编辑写入原账号恢复快照；停止新任务派发；已提交到外部的生成任务只做内部收尾，结果写回原账号，不继续展示给无授权用户。首期同一桌面进程只激活一个账号；切换账号前，明确提示先完成/停止本地活动任务并保存，避免为多账号并行后台运行另造调度器。
- 中央登录限流，日志不记密钥/令牌，用户变更和对应审计在同一事务中提交。对同一用户授权修改带 revision，过期版本返回冲突；重复创建由唯一账号阻止。审计服务异常时拒绝管理员变更，不假报成功。

### 3、隔离和接口

云端 Web 的项目、媒体、任务、模型配置、模型默认值、业务账本增加 owner_user_id，查询/更新必须含所属用户条件；原以 kind 或固定 owner 为主键的表相应改成按用户唯一。素材下载包括 Range 请求也校验归属。普通会员对自己的收益/渠道账本仍有全部原功能，不能管理别人的账本或平台用户。

桌面按中央 user_id 使用独立工作目录，覆盖 D1/R2、模型配置、豆包账号与任务。旧单工作区保留备份并明确认领，不默认归给第一个新登录用户。先实现单账号运行，避免账号切换后媒体、模型密钥和任务串用。

建议复用现有壳、组件和 API 规范；只按需要抽出登录门禁及后台模块，不趁机重构整个 app/page.tsx。接口最小集合：

- `/auth/login`、`/auth/me`、`/auth/logout`：登录、验证和退出。
- `/admin/users`：列表/创建；`/admin/users/:id/authorization`：期限调整；`/ban`、`/restore`：封禁恢复。无 DELETE。
- `/admin/users/:id/usage`、`/admin/overview`、`/admin/audit-logs`：分页与日期查询。
- `/usage/events`：批量上报，服务端确定 user_id，不信任客户端任意指定用户或角色。

错误区分未登录、无权限/到期/封禁、输入错误、修改冲突、限流和服务故障。登录密钥遗失由管理员受控重新设置（必要维护能力，可在后续迭代增加页面），本期不做自助找回或旧密钥明文查看。

## 四、统计与日志

### 1、统计口径及埋点

统计从功能上线开始，不从现有项目快照编造历史。按北京时间归日，失败不计成功，普通会员到期/封禁前的记录保留，超管活动不进入会员总数。

| 指标 | 计数规则和位置 |
|---|---|
| 创意 | 新项目首次成功保存非空 brief 记 1；同项目改写/保存不重复，导入旧项目不计新创意。位于 projects 保存接口 |
| 故事 | 生成成功且完整性校验通过的故事候选，每个记 1；一次 3 个候选计 3。位于 ai 接口，共用业务解析规则 |
| 剧本 | 生成成功且完整的剧本输出，每份记 1；编辑/重复读取不计。位于 ai 接口 |
| 素材 | 图片、视频、音频成功入库，每个独立 media_id 记 1；生成、上传、豆包回传区分来源；引用复用、缩略图和重复回调不计。盘点所有媒体写入路径后统一记事件 |
| 导出视频 | 系统成功新写出的每个视频文件记 1，video_kind 区分 shot/final；已有文件再次打开或定位记 0；失败、取消、草稿、剪辑包不计 |

当前 `desktop/main.cjs` 的 `director:reveal-video` 调用 `desktop/video-files.cjs::exportVideo`。该函数既可能新写文件，也可能直接返回已有文件，不能每次返回成功都加 1。改为返回 `{filename, created}` 并同步调用处，成功创建新文件才生成导出事件；并发文件已存在也返回 created=false。沿用原文件保护，不覆盖用户副本。

**首期接入现有分镜视频文件导出，不能把第五项整项留空。**最终成片尚无可靠回执，仅 final 子项显示“尚未接入”；大盘标注当前覆盖的导出类型。外部剪映导出、render.py 成片、浏览器仅触发下载都不能自动当成已确认成功；未来接入实际完成回执再扩展 final 子项。剪映草稿/剪辑包预留独立事件类型，不混入视频指标；本阶段不把下载触发当作成功回执。

### 2、可靠性保留到必要程度

- 每个完成事件带稳定 event_id（包含操作和产物标识），中央用唯一约束去重；重复轮询/上传不会重复累计。多个输出有不同 output_id，唯一字段不使用 NULL，重试不重新分配 ID。
- 桌面只增一张本地待上报事件表（含同步状态），无需单独消息队列。业务完成写本地事件，在线批量上传，失败保留重试；中央已收到但确认丢失时重传不重复计数。
- 文件导出保留最小操作记录：生成固定操作 ID、写入目标、标记完成和待上报状态；重启核查已成功写出的文件后补记，解决写完文件但上报前退出的漏数。无需中央预登记每次创作、签发专用任务凭据或建设计费级事件认证。
- 若账号授权失效导致无法继续上报，完成记录留在原账号本地，重新获准登录后补传。中央显示最近接收时间和“桌面上报可能延迟”，不承诺未联网设备的实时完整数据。收尾写入不恢复业务访问权限。
- 事件记录操作发生/完成时间和接收时间，迟到记录回到正确业务日；身份归属于原发起用户，不因后来登录另一个账号而改变。桌面时间存在可信度限制，明显异常时间单独标记，不伪装成计费账本。
- 只收数量、类型、时间、状态、稳定标识，不收用户正文、素材内容、模型密钥。本期数据用于使用情况观察，不设计防作弊收费系统。

### 3、管理员日志

覆盖管理员的已提交操作：登录/退出、页面访问、列表/统计/详情/日志查询、新增用户、期限调整、封禁恢复，以及失败结果；业务生成/保存/导出同样留语义记录，但不混入普通会员大盘。不记录每个按键、草稿输入或明文密钥。

每条保存服务端时间、操作者 ID/账号、目标 ID/账号、动作、前后变化、原因、成功/失败、请求 ID。查询自动记条件，变更原因由管理员填写；日志只读、不可编辑删除；查看日志不递归触发查询。用户变更与审计事务化，基础数据定期备份即可，本期不加区块链、复杂签名链或独立审计平台。

## 五、开发顺序与验收

1. **中央基础**：确认部署入口，创建四张表、初始化超管、登录/会话/限流、授权和审计基本函数。先用独立测试数据。
2. **接入现系统**：登录页与门禁、Web API/桌面 IPC 权限检查、数据归属与旧工作区认领；复用原页面和主题。测试登录前无界面闪现、退出/到期/封禁、断网和任务收尾。
3. **管理后台**：创建用户、期限调整、封禁恢复、查询日志；验证无删除、无会员入口、普通会员全功能保留、直接请求后台被拒绝、并发修改冲突。
4. **统计接入**：五项计数、统一事件、桌面重试；验证多候选、重复保存、素材重复回调、视频新写/重复打开、崩溃补传、跨日、用户明细求和等于大盘、超管不计入、新用户零历史。
5. **交付**：双主题交互与相关原创作链回归，中央备份恢复、Windows 实机、独立数据迁移；重建 runtime、递增桌面版本、新建独立发布目录。按本次明确授权再提交/推送/发布，不覆盖运行中的程序。

需明确的边界：旧版离线程序没有门禁，新增中央服务不能强制远程停止旧版或收回已导出的文件；新版本本地代码也不是不可破解的 DRM。中央账号、管理员和统计接口已部署；桌面门禁、账号工作区、管理界面和统计上报已实现并完成隔离联调；尚未发布新桌面安装版，Windows实机及最终交付留第五阶段。后续新需求先扩展现有表字段和模块，达到实际容量/角色需求后再增加专门系统。
