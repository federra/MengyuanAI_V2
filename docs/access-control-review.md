# 授权 Demo 与方案：需求对照审阅

日期：2026-09-15。审阅依据：用户确认的三类身份、两类页面、六项管理员能力，以及本轮“不要过度设计”和导出视频统计口径补充。结论：原稿方向可用，但有范围偏差和演示断链；本轮已修订。正式系统尚未开发。

## 一、主要发现与调整

| 项目 | 原问题 | 本轮调整 |
|---|---|---|
| 需求范围 | 文档曾把收益/渠道账本管理移给超管，削减普通会员功能；把会话/联网等建议写得过于强制 | 保留会员全部原业务功能，隔离各自数据；用户确认要求与实现建议分开；仅新增平台后台属超管 |
| 登录与授权 | 原型创建账号后不能用新密钥登录；封禁、延期仅改列表；管理员不能正常回到原工作台入口；登录页可直接切身份 | 登录和管理共用模拟用户状态，支持新增账号登录、封禁拒绝、到期拒绝与恢复；两角色先进入工作台；默认无场景选择，review=1 才开放评审工具 |
| 使用统计 | 历史数字由公式拼接、明细重复占位，新增零使用用户仍能出现历史记录；第五项被过度缩窄为最终成片后整项延期 | 汇总、趋势、明细同源，零使用用户无事件；按补充确认接入系统视频文件导出，分镜/成片分列；重复定位不计数，未接入成片只标子项 |
| 操作留痕 | 缺登录退出、查询、翻页、失败等记录；日志没有稳定 ID，时间与模拟日期混用；翻页记录自己又导致列表偏移 | 增加操作者/对象/原因/结果/秒级时间/记录 ID，补覆盖；密钥不入日志；日志分页使用查询快照；明确业务操作和输入按键的区别 |
| 开发复杂度 | 原案提前规划 usage_daily、独立幂等表、中央操作预登记/专用回执等；超出早期所需 | 中央四张表，索引聚合；桌面只保留必要待上报记录和重试；保留稳定用户/事件 ID 和视频类型供后续扩展，不提前建设计费/分布式平台 |

## 二、页面步骤与本轮验证

1. **登录：通过。**默认无业务导航与角色选择；直接追加 view=admin 仍是登录。大小写规范化后的超管登录进入原工作台占位，超管后台入口紧接系统设置。
2. **用户管理：通过。**浏览器创建 qa.flow/自定公开测试密钥，显示有效、尚无创作活动。退出后用新账号成功登录，显示真实模拟备注名和期限，后台按钮数量为 0；超管封禁后同一凭据被拒绝。
3. **使用明细：通过。**新用户当天/历史五项为 0，明细为空；林导演当日共 110 个事件，与 12+24+8+63+3 一致。翻页、指定 2026-09-10 查询返回该日事件，查询同步写日志。
4. **日志与视觉：通过已测范围。**查看本轮登录、访问、翻页、日期查询、主题等记录；浅色日志和深色后台、深色登录截图已在当前会话浏览器工具结果中检查。检查了默认视口及 1024×768 桌面窄尺寸；临时视口已恢复。键盘左右切换后台标签成功，浏览器 error/warn 读取为空。
5. **状态回归：通过。**test-state.mjs 验证新账号登录、无权限直接改用户被拒、封禁/恢复、截止时间前 1ms 与截止时刻、恢复不延期、延期不解封、历史求和排除超管、新用户无历史、用户记录保留、日志无测试密钥。

本轮未执行生产构建或原模型流程：修改范围仅为文档和独立 Demo，无生产业务源码变更。已执行 JS 语法检查、状态回归、文档相对链接检查、git diff --check。上述状态测试针对模拟行为，不证明真实后端安全性。
