# 剧本资产缺描述与错位排查

## 一、结论与提取时机

本轮在共享业务源码中复现了资产丢失、空描述去重和明显依据错配问题，已修复源码；没有取得反馈用户的 Windows 版本、原剧本、模型原始响应或项目文件，不能据此认定该用户的具体触发原因，也不能称为 Windows 实机复现。未打包、发布或修改用户项目数据。

资产有两条来源，并不是统一等分镜生成完再提取：

- `components/asset-sync.tsx`：剧本非空且需要重新扫描时，等待约1.8秒，通过 `/api/assets` 独立调用文本模型提取全文资产。任务常驻，不依赖用户当前是否停留在剧本页；与分镜生成不互相等待。已扫描剧本不会无条件反复调用，可手动重新整理。无模型或失败时，只从明确标签和带引号的对白中保留名称，描述可能为空。
- `app/api/ai/route.ts`：剧本转分镜按段调用模型，响应可以携带 `assets` 或 episodes 格式的 `missing_roles / missing_scenes / missing_props`。服务端逐段校验并合并，用户应用后由 `applyStoryboardImport` 加入项目。是否完整返回描述取决于所选 Skill、模型和输入。

独立全文提取使用 `app/api/assets/route.ts` 的固定提示词，不读取用户选择的分镜 Skill，也没有自动接入文档目录里的资产提取 Skill。两条来源最后按“分类＋名称”合并至 `Project.assets`。

## 二、复现与修复

| 问题 | 可复现条件 | 源码修复 |
| --- | --- | --- |
| 异步旧快照覆盖 | 应用分镜等待格式校验时，后台资产提取先写入；反向顺序下，资产提取也可能用旧项目覆盖刚应用的分镜 | 应用分镜以提交时的项目为准；AssetSync 提交合并函数而非旧项目对象；两个入口立即同步当前项目引用，保留最新资产与分镜，并再次核对项目和剧本身份。保留资产版本处理和应用前撤销快照 |
| 后续描述被去重丢弃 | 同分类同名资产第一项描述为空，后续重复项有描述；可发生于独立提取、单次导入、episodes 或跨剧本段合并 | 四处去重均允许后续非空描述补齐空项，不覆盖已有非空描述 |
| 原文依据张冠李戴 | 原文中有小林与小王，模型给小林返回“小王穿蓝衣”的依据；旧代码仅验证这句话存在于全文 | 当稳定资产名称出现在原文中，要求依据也包含该名称；人物配音使用角色名核对。明显不对应的描述不自动采用并给出警告；提示词补充对应身份与描述要求 |
| 空项和冲突被隐藏 | 标签兜底没有描述仍记为已扫描；两路生成描述不同，保留旧描述、新描述存入 `suggestedDescription`，但分镜资产弹窗不显示它 | 缺描述明确提示；分镜页和资产中心显示扫描状态，资产弹窗可进入状态/重试页，逐项查看原文依据及新旧描述，选择采用或保留；失败后的空标签兜底不再清掉待复核的新描述 |

资产弹窗原本按资产 ID 编辑，行序号只作显示；本轮没有发现按数组下标把另一行描述写入的证据。不同来源的描述冲突原先保留旧值，是保护人工设定的规则；修复增加可见的复核入口，不自动覆盖人工描述。

## 三、验证与范围

新增 `tests/asset-consistency.mjs`：8项回归覆盖两种异步顺序、错误原文依据、空描述警告、四条去重链路中的单模块行为和待复核描述保留。旧代码先运行失败，修复后通过。跨段去重另加到 `tests/storyboard-flow.mjs`。新增 `tests/asset-review-ui.mjs`，用真实组件服务端渲染确认空描述、依据、冲突及复核入口可见，媒体和弹窗容器依赖采用无副作用替身；不等同于 Windows 窗口交互验收。

回归范围：`core`、`asset-consistency`、`assets`、`repair-flow`、`asset-review-ui`、`episodes`、`storyboard-normalize`、`storyboard-flow`、`project-save-race`。`repair-flow` 的旧模拟环境缺少后来新增的用量模块与数据库 batch 接口，本轮补齐测试替身；业务保存接口未改动。测试中的 502 日志来自故意模拟模型额度错误。

本轮未使用真实付费模型。名称与依据匹配只能拦截明显错配，不能证明每个描述在语义上都正确；别名、代词、同句多人和模型凭空生成的设定仍需原文复核。空描述可能确实来自原文未提供视觉信息，不应为了填满而虚构。已有项目的非空错误描述不会被静默重写，需要在修复版重新整理并审阅新描述。

运行检查：上述回归、TypeScript 类型检查、定向 lint、Web 生产构建。此文只记录本轮源码验证，不代表已安装 Windows 版获得修复；交付安装版需另行构建和发布。
