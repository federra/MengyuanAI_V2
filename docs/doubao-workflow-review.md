# 豆包插件工作流程核对（2026-09-12）

依据用户提供的梦源AI界面、运行进程、本地 Electron Helper 管理模块、工作台界面模块，以及只读 SQLite 表结构和汇总记录进行核对。未修改梦源AI的账号、任务或配置，未提交视频生成。

## 已确认的机制

- Electron 主进程管理独立的本地 Helper，界面通过 IPC 调用它；Helper 提供账号、任务、打开账号目录、取消未完成任务及重取结果等接口。
- 每个账号绑定 Chrome Profile；任务保存提示词、图片数、模型、时长、画幅、远端任务编号、原对话地址和视频链接。
- 账号记录每日次数、额度、冷却时间及连续失败数。数据库中存在这些字段，不等于已确认其所有运行规则。
- 当前数据库有16个账号和25条任务，其中24条成功且有视频链接，1条失败；这是该软件的历史数据，不代表本工作台的生成验证结果。
- 工作台可按状态分页读取摘要，按远端任务编号重取视频；“重取”和“重新生成”属于不同操作。
- 可批量打开可用账号；清理记录与删除已下载文件在界面上分别处理。

## 本工作台本次改进

1. 批量打开仅处理当前分组已勾选“调用”的账号，跳过已占用、正在检测登录、页面忙碌和达到配置额度的账号，逐项报告成功、跳过与失败。打开浏览器不直接视为可接单，仍保留登录和空闲检测。
2. 下载前保存已匹配的原始地址。网络或回传失败时可重试下载；地址失效时清除旧地址，下一次按已保存的视频编号重新查询原始播放信息。需要时打开原账号独立浏览器。
3. 重取保持原任务、账号、视频编号及提交计数，不重新发送提示词、不再次点击生成。重复点击同一次重取不会创建新任务；其他待核对任务仍占用账号。
4. 任务记录增加搜索、每页5/10/20/50条、重取次数和已找到原始视频的提示。

继续保留账号分组轮询、单账号串行、暂停/恢复、原台词与图片对应关系、原始视频回填、手动替换/删除视频等既有功能。

## 核对边界

本次没有读取凭据或破解加密配置。Helper 内部打包二进制的全部生成细节未得到验证；不将数据库字段或界面名称当作完整实现证据。本次实现为独立编写，未移植第三方程序代码。恢复播放信息沿用本项目已有协议，外部服务真实结果还需实际账号任务验证。未自动重置平台真实额度，也未推算真实积分。


## 0.1.39 自动提交修复

实际账号管理数据中存在待排队任务，但旧入队代码未启动账号浏览器。默认空的运行/空闲选择器阻断派单，默认 textarea 无法兼容部分富文本输入区；一次准备失败后也不再自动尝试。

- 入队后启动所选分组内可用账号的独立 Chrome，检测登录；登录或验证期间保留窗口等待，成功后继续准备，不按普通登录检测流程提前关窗。启动和登录中的账号计入并发数。
- 默认内置 AI 创作输入区识别，自动切换视频、核对分镜模型/比例/时长。只有高级手动适配需要配置选择器。
- 支持 textarea、contenteditable 及唯一的门户文件控件；按图片顺序传入文件，原提示词保持一致。等待附件数量、可用发送按钮和已观察到的二进制上传请求结束；控件有歧义时保留错误而不盲点。
- 页面短暂未就绪时有限重试；尚未点击提交的失败任务提供“重新准备”。已尝试提交的任务不自动重复点击，原任务结果查询与重取规则保持不变。
- 参考软件的静态浏览器适配脚本进一步确认了富文本编辑器、独立文件控件及 flow-end-msg-send 入口。只提取定位事实，独立实现；未移植第三方源码。

验证：真实本地 Chromium 测试普通/富文本输入框、门户上传控件、图片顺序、原文填入、参数核对、一次点击及上传期间阻止发送；管理器测试入队自动打开、登录等待、并发占用、暂停与重试。已有调度、登录、结果恢复及防重复提交测试通过。没有使用真实豆包账号上传或提交付费生成，线上页面变更仍可能需要进一步适配。


## 0.1.40 启动流程简化

再次读取实际管理记录：06:00 的旧任务留下 purpose=generation 的 pending 登录检查，后来取消；06:01 新任务没有启动记录，随后被暂停。扩展的本地诊断也曾停在“必须只保留一个豆包标签页”。这些记录不足以证明当时浏览器可见，用户反馈本次没有打开浏览器。

生成流程不再新建独立登录检测任务，旧 generation 检测不占用下一次启动。入队或恢复会启动所选账号；窗口恢复显示，扩展复用创作页，多条历史标签页不再阻断连接。实际登录/验证页面仍会等待本人处理，昵称仅用于显示。后台故障直接回传工作台任务记录。

保持单账号独占、两次空闲观察、实际登录/验证阻断与防重复提交。回归覆盖旧取消任务残留检查、新任务立即打开、无昵称但创作页就绪、多个标签页、历史页保留、账号窗口激活和暂停。当前用户队列仍保持暂停，没有擅自恢复或消耗生成次数；未验证真实豆包生成结果。


## 0.1.41 创作页导航与脚本启动

最新任务处于 queued，启动记录含 Execution context was destroyed。代码存在确定的循环前置条件：派单要求创作页控件已出现，但进入 AI 创作的代码只在派单后执行。另在从空标题页面开始的完整 Chromium 测试中复现账号标题 MutationObserver 无限写入，导致页面无法执行后续动作。

- 将进入 AI 创作移到派单前；普通对话的未发送草稿、运行任务、登录验证仍会阻止跳转。已提交任务不跳走。
- 账号标题按 document.title 的空白规范处理，避免空标题的观察器循环。
- Chrome 设置页上下文切换有界重试，每个浏览器会话仅设置一次开发者模式。
- 没有占用任务时重载自有扩展，使用新的创作页加载最新脚本；已有任务不重载。通过事件回报实际脚本版本，区别于磁盘 manifest 版本。重载采用 Chrome runtime.reload 官方接口：https://developer.chrome.com/docs/extensions/reference/api/runtime#method-reload 。

验证：真实 Chrome 隔离测试通过扩展加载、重载、连接、开发者模式保存与重启；真实 Chromium 本地页面测试从普通对话、未派单开始，依次进入 AI 创作、设置视频参数、按图号上传、保持提示词原文并只点击一次。保留草稿回归和现有账号独占/暂停/登录测试通过。没有提交用户真实豆包任务或验证其视频结果。


## 0.1.42 失败状态与重新生成

结果超时、返回失败或下载失败统一在豆包任务列表和分镜显示“生成失败”，停止转圈，提供重新生成。排队和进行中的任务不因暂时没有视频而判错。内部 attention 保留原账号运行状态未确认的区别，用于结果重取和账号互斥，不再作为界面的运行状态。

重新生成创建独立新任务，保留旧记录、原始图片顺序和台词；分镜入口使用当前分镜设置，任务列表入口复用原任务包。重复点击同一旧任务不会重复建单。原账号离线时自动打开，连续检测空闲后释放占用；暂停时拒绝新增。重试在新创作页执行，保留旧对话，旧结果不能覆盖新的生成。

验证：超时/暂停/重复点击/原任务包复制/离线重新打开/忙碌与两次空闲/计数不重复/旧回调隔离测试通过，重试新页面只打开一次，原有调度和下载恢复测试通过。未提交真实豆包生成。


## 0.1.44 视频模式切换与失败诊断

用户确认卡住时仍显示 Seedream 4.5，因此是真实切换失败。运行日志有“未确认已切换到视频模式”，实际扩展回报仍为 0.11.0。修正准确文字控件点击：不再上溯祖先而跳过内层点击处理器；等待 SPA 更新后校验，Seedream 明确阻止继续。无占位符时允许 Seedance 与时长控件联合确认。URL 未就绪不会再抛 Invalid URL。

准备失败保留工作流错误，不被空闲心跳清空；三次失败转为界面失败，可手动重新生成，仍保留未确认提交状态的账号锁。账号页明确提示实际运行助手版本不一致。

验证：本地真实 Chromium 三种页面（textarea、richtext portal、延迟切换且无占位符）使用内层文字绑定事件，按序上传/准确提示词/仅一次提交通过；模式负向校验与任务重试回归通过。未读取真实豆包 DOM，未验证线上视频生成成功；该点击修复是代码缺陷修复，不能视为已证明真实页面的唯一根因。


## 0.1.45 独立浏览器默认自动更新

桌面启动仍将随软件交付的插件同步到本机目录；在线助手回报执行版本，和当前版本不同则先阻止新的派单。旧助手在同一桌面会话、账号空闲且没有占用任务时通过现有 Chrome 私有管道重载；不为后台更新启动离线账号。0.12.0 起助手支持工作台授权的空闲自更新，因此后续桌面升级重启不依赖旧管道仍存活。

运行、下载、未确认结果的账号延后更新；暂停队列可以更新但保持暂停。更新许可与派单串行，运行版本确认前不分配新任务；持久化更新进度、60秒重试间隔，避免重载死循环。更新后打开后台创作页以加载新版主世界观察器和转发脚本，保留原对话、草稿与登录资料。UI显示自动更新状态。首次安装本版桌面需正常重启一次，未引入软件自身的在线下载安装功能。

验证：真实隔离 Chrome 从旧扩展文件升级至当前版本，读取实际 service worker 的代码标记确认已更新，PID和登录目录不变，未打开的账号不会被更新程序启动。调度回归覆盖原任务占用、更新锁、旧版确认无效、新版确认放行、暂停状态保留；扩展回归覆盖页面忙碌、授权拒绝、自重载、后台新页面与连接数据保留。未使用用户豆包账号或提交视频。
