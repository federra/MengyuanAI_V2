# 图片尺寸审查与修复

用户的失败记录使用`doubao-seedream-4-5-251128`及`seedream`协议，服务商明确返回最低3686400像素。任务旧记录没有保存size，不能声称从记录读到了实际宽高；源码中六种默认比例均低于该门槛，已复现并修正。

## 尺寸清单

| 画幅 | 原默认尺寸 | Seedream修复后 |
| --- | --- | --- |
| 16:9 | 2048×1152 | 2560×1440 |
| 9:16 | 1152×2048 | 1440×2560 |
| 1:1 | 1536×1536 | 2048×2048 |
| 4:3 | 1792×1344 | 2304×1728 |
| 3:4 | 1344×1792 | 1728×2304 |
| 21:9 | 2688×1152 | 3024×1296 |

Seedream保留2K/4K档位。自定义比例等比放大并向上取8像素倍数；在本系统256～4096像素单边限制内无法满足最低总像素的极端画幅明确报错，可改用常用画幅或档位。后端在首次请求前修正旧客户端的低像素尺寸，不重试已失败任务。

GPT Image备选1024×1024、1536×1024、1024×1536；DALL·E 3备选1024×1024、1792×1024、1024×1792；DALL·E 2备选256×256、512×512、1024×1024。其默认按横/竖/方选择兼容尺寸，界面不再称与视频比例完全一致。未知OpenAI兼容服务沿用通用备选，具体支持范围仍取决于服务商，不把已知型号限制强加给未知型号。

模型切换后无效选项回退到当前模型的默认兼容尺寸。单张、资产批量与后端使用同一规则。视频分辨率仍由原有视频模型协议控制，本次没有把图片尺寸规则应用于视频输出。

## 验证与状态

`tests/seedream-size.mjs`覆盖全部六种画幅、自定义画幅、2K/4K、已知图片型号的全部菜单尺寸和错误尺寸；`tests/models.mjs`模拟真实提交链，验证旧2048×1152在第一次服务商请求中变为2560×1440且仅调用一次。模型、项目保存/恢复回归、类型检查、lint和构建通过。未调用付费模型，未修改密钥、未重试旧任务，未发布安装包。

参考：[Seedream 4.5提供商尺寸说明](https://novita.ai/docs/api-reference/model-apis-seedream-4.5)、[OpenAI官方SDK尺寸定义](https://github.com/openai/openai-node/blob/main/src/resources/images.ts)。
