# 分镜格式转换与资产管理调整

## 分镜入口

从剧本生成分镜的`/api/ai`、分镜JSON导入，以及编辑AI结果后的应用，统一通过服务端校验。公共逻辑在`lib/storyboard-normalize.ts`，模型适配在`lib/storyboard-conversion-server.ts`，导入入口为`POST /api/storyboards/normalize`。

合法内容不调用AI；不符合模板时使用当前默认文本模型转换一次，转换结果重新经过实际导入器与项目校验。可识别的原视频段数量、每段时长和结构化原台词必须保留；失败不写项目、不自动循环重试。未知结构中的语义保真仍需用户审阅，不能把通过结构校验等同于内容完全正确。生成保留原有结果预览，导入保留检查及确认应用步骤。

转换提示为“剧本格式转换中”。导入转换期间锁定输入，项目切换后丢弃过期结果。合法输入最多200万字；需要AI转换的输入最多60000字，超出时明确提示分批。未配置默认文本模型时，合法JSON仍可导入，非法格式会提示模型错误。转换会消耗用户所配置文本模型的额度，不调用图片或视频模型。

## 资产管理

未设置的角色默认启用三视图及内置“角色三视图生图”Skill；显式取消、选择不使用Skill或其他Skill均保留。取消三视图时，如果正在使用内置三视图Skill，同时取消该Skill，避免提示词仍要求三视图。场景及道具不启用角色默认值。

管理表使用有界滚动区域与固定表头。生成结果分别提供“预览”和“应用/替换”，预览弹窗内可确认应用，直接应用不弹预览。清除图片同时记录`dismissedImageId`，解除当前引用并防止同一历史结果又显示为待应用图；保留生成任务与媒体文件，新生成的不同图片仍可出现。修改后仍需保存项目。

三个管理页的“图片目录”使用系统原生文件选择器定位当前账号/项目原有导出目录；有当前图时先导出，再可选择PNG/JPG/WebP历史图片直接应用。清除后仍可选图，取消不改变引用。选图后通过鉴权本机API复制到素材库，不依赖外部文件以后仍在原处。文件上限50MB，主进程检查签名及大小；浏览器版本提供文件选择。操作沿用项目保存流程。

## 外部分镜Agent格式导入修复（2026-09-22）

识别字段完整的 `storyboards + voice_registry + missing_elements` 格式，先做确定性映射，再通过实际导入器与项目校验；无需让模型重写已确定的台词/提示词。逐字映射content中的kind/speaker/text/emotion、完整prompt、数值秒数、资产引用及音色。原始来源、连续性与统计保存在可选 `Shot.sourceMetadata` 字符串（最多10000字），导入、保存和导出保留，不混入视频生成提示词。未知/歧义格式仍按原流程最多调用一次AI；不放松台词/数量/时长保护。

AI兜底使用紧凑shots结构转换提示，不要求扩写复杂episodes。明确区分输出长度截断、空内容和其他提前终止；若服务未提供finish_reason而JSON完整，则交给实际解析器验证，不仅凭缺少该可选字段拒绝。无法从用户两条错误提示还原首次供应商原始响应，不声称已证实其具体finish_reason。

用户提供的code.json只读重放通过：6段、60秒、7条台词和全部提示词逐字一致，15项资产（含声音），零AI调用；不将用户原稿加入Git。新增合成数据回归覆盖确定性映射及元数据；接口测试覆盖截断提示及缺少finish_reason的完整响应。
