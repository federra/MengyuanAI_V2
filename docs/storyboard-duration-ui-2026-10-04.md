# 分镜时长与资产界面调整（2026-10-04）

## 问题与原因

用户要求移除分镜工作区的大块资产整理卡、资产管理描述下方的依据和差异说明；同时反馈分镜预设时长超过15甚至20秒。

分镜通用导入契约 `lib/storyboard-contract.ts` 允许0.1～120秒，生成接口直接复用；表格输入上限也是120秒。视频API的已有通用校验却要求2～15整数秒，豆包设置原来甚至允许60秒。生成与视频能力脱节，完整合法的JSON也能产生无法提交的视频段。这是项目规则的问题，不能归因于模型输入字数或Windows环境。

## 实现

- `app/page.tsx` 只在资产页/资产中心显示 `AssetSync`，分镜页隐藏卡片；组件仍挂载，保留独立后台提取和并发合并。
- `components/project-asset-dialog.tsx` 移除所有共用描述单元格下方的空描述说明、原文依据、差异说明和采用/保留按钮。数据字段、手工描述和顶部识别状态入口保留。
- `lib/video-duration.ts` 集中列出已接入适配器的约束：通用2～15整数秒、黑马GROK 6/10/15、MiniMax H3 5～15、Firefly VEO按完整型号固定秒数；豆包4～15，依据项目已有滑块适配规则。未声称未知服务商均支持全部这些时长。
- 分镜生成读取默认视频配置，用生成专用时长约束覆盖通用导入范围，要求完整保留剧情/对白、按演出时间增加视频段并重建时间轴。模型返回后逐段校验；不符合时最多额外重新生成当前剧本块一次，再失败则返回错误，不应用任何分镜。该修正会额外消耗一次文本请求，进度明确提示正在重新拆分。输出截断的既有有限拆块处理与此分别计数。
- 分镜表时长输入上限按行的渠道设置；旧值不自动缩短，展示问题和“重新生成项目分镜”入口。此入口从当前剧本生成整项目分镜，仍须预览确认后替换，不表示只修改当前一行。原有JSON导入保真规则保留，长段导入不暗改时长或内容，视频提交独立拦截。
- 视频弹窗在提交前校验允许时长，豆包任务包生成和主进程入队均检查；主进程先校验整个批次，含超长项时全部不入队。缺时长的旧任务仍按插件默认值检查，保留原兼容方式。

## 验证与交付

- 首先用完整合法的22秒模型响应重放，原实现直接返回1条，回归失败；修复后模拟AI重拆为10+12秒，两句对白和总时长保留。第二次仍22秒拒绝应用、两次请求有界；固定8秒型号和长段导入保真通过。此处为模拟模型，不能据此承诺真实AI的叙事质量。
- 14个相关Web/库测试脚本通过，包括资产并发、资产弹窗渲染、分镜生成/导入、模型预算及豆包参数；隔离豆包主进程和失败重试测试通过，验证超长批次无部分入队。
- 类型检查、相关TS/TSX定向lint、CJS语法检查、diff空白检查及Web构建通过。扩大lint到历史CJS/DOM测试时发现既有require/未使用解构变量及DOM废弃标记告警，HEAD基线复核一致；未以无关整改扩大本次修改。
- 新独立目录 `desktop/release/v0.1.108/mac/`；真实编译页面的隔离Electron测试在1450/1024/760宽度及深色主题通过：3条样例分镜可见、资产状态卡不存在。截图已查看，用户项目和真实模型未改写。
