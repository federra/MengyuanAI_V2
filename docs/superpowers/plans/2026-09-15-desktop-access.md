# 第二阶段：桌面账号门禁

依据：已确认的 docs/access-control-design.md，用户授权继续第二步。沿用既有 Demo 视觉和中央四表，不引入新角色/订单。

- [x] 主进程 AccessSession：HTTPS 登录、只在内存保存 token、在线逐请求校验、并发校验合并、失效通知、退出。测试错误凭据/断网/撤销/竞态，不用真实用户凭据。
- [x] AccountWorkspace：按中央 UUID 独立目录，目录设置/模型加密密钥/豆包资料归属账号；旧目录明确选择认领并复制，原件保留。单进程绑定一个账号，不同账号切换需安全重启，防止任务和浏览器资料串用。
- [x] Worker 经 Miniflare service binding → backend 宿主 IPC → 主进程授权；保护所有 /api 请求和媒体 Range。主进程敏感 IPC/菜单同样校验。豆包停止新派发，已提交结果允许以内部通道收尾。
- [x] 登录前只渲染 LoginGate，不挂载 Home；深浅主题；心跳/焦点更新，授权失效卸载业务；未保存项目持续写当前账号恢复快照并在下次登录提示恢复。退出前确认活动任务。
- [x] 本地测试、真实 Worker 集成、构建、独立 Electron 登录烟测；更新文档。桌面交付统一第五阶段，本轮不替换正在运行的程序、不修改快捷方式、不发布安装包。

范围说明：本阶段针对已部署中央服务＋桌面单用户进程。独立云端 Web 业务库的多人 owner_user_id 迁移没有部署环境，本轮不开放浏览器直连业务；共享页面可构建，但云端业务入口必须默认拒绝，待独立 Web 部署时再启用其会话与所属关系。中央管理 HTTP/后台页面仍第三阶段。
