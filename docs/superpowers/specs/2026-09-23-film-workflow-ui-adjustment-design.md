# AI 短片工作台：用户参与的工作流与 UI 调整方案

日期：2026-09-23。状态：方案，未实施、未升版、未发布。已纳入用户最新澄清：“一句话到一部 AI 短片”是产品目标的比喻，用户必须参与选择、编辑、确认和生成控制。本版替代本轮此前未实施的扩大范围草稿；内置 MP4、完整剪辑和自动派发系统不作为本次必做项。配套：[实施清单](../plans/2026-09-23-film-workflow-ui-adjustment.md)。

## 一、目标与工作流：保留用户的创作决定权

**推荐结论：保留当前业务主线，调整现有 UI。** 以澄清后的同等交付范围初估，调整约 12 工程人日，重做约 26 工程人日，节省约 54%，达到用户“节省 50% 以上选择调整”的门槛。估算不是实测；P0 用一个真实分镜的改造验证复用边界后重新核算。

目标是让用户每一步都知道：当前处理什么、能改什么、下一次生成会使用什么内容、结果如何采用。AI 提供候选和执行能力，用户决定创作方向与进入下一步的时机。

主线：**输入 idea 或导入成品故事 → 生成 X 个故事备选（导入故事可跳过）→ 比较、选定或人工编辑故事 → 生成并编辑剧本 → 生成并编辑分镜 → 按需要制作角色/场景/道具/站位图，或直接生成视频 → 成品导出。** 成品导出沿用现有创作工作台的预览、配音/BGM、剪映草稿、分镜/项目 JSON、SRT 与完整剪辑包能力，不是新增环节。

| 环节 | 主要页面内容 | 用户决定 | 主动作与结果 |
|---|---|---|---|
| 创意输入 | idea、风格、画幅、篇幅、故事数量 X；高级参数可展开 | 决定目标、生成数量，或导入现有故事 | “生成 X 个故事方案”；导入直接打开故事编辑 |
| 故事选择 | 候选列表＋当前正文，区别预览版本和已选版本 | 比较、选用、手改或另存候选 | “用当前故事生成剧本”；使用按钮附近显示的正文 |
| 剧本编辑 | 剧本正文为主，修改建议与版本为辅 | 修改剧情、对白、节奏；必要时再生成 | “用当前剧本生成分镜”；新结果先预览、再应用 |
| 分镜编辑 | 紧凑镜头总览＋展开的单镜头详情 | 改画面、时长、台词、引用及顺序 | 当前镜头的“生成素材/生成视频”；总览显示准备情况 |
| 素材制作 | 镜头与角色/场景/道具直接关联，站位图属于镜头 | 选择需要的图片/参考，或直接视频；审阅后替换/保留 | 本次生成对象、模型、参考和范围清楚；结果回到原对象 |
| 成品导出（已有环节） | 镜头顺序预览、画面检查、配音/BGM/字幕及导出选择 | 检查并修正缺项，选择剪映草稿、字幕、JSON或完整剪辑包 | 导出实际支持的产物；最终MP4仍由剪映或外部工具完成 |

故事和剧本是不同创作决策，不合并为一个确认步骤。保留 X 可配置，沿用当前默认 3 和现有数量校验，不擅自固定为两个故事。不新增额外“审批页”：点击“用当前故事生成剧本”本身就是对本次输入的确认；覆盖与消耗范围在现有提交位置说明。

素材是可选分支，不是必须完成的关卡：需要稳定形象时“复用/生成资产图→按需站位图或首帧→视频”；快速试镜头时“分镜文字→直接视频”，是否允许无图由模型能力决定；已有素材时直接上传或引用，不强制再生成。“先试一个镜头”可以作为快捷选项，不能强制或自动增加付费调用。

## 二、页面应该怎么改

### 1、保留阶段导航，减少重复操作区

保持现有创意、故事、剧本、分镜、成品导出五阶段映射，不新增一套路由或项目状态。分镜内安排“镜头工作区 / 项目资产”两个视图；任务作为随时可打开的结果入口。侧栏按创作、收益/渠道、设置分组；管理员后台仍紧接系统设置且仅超管可见。

项目顶栏保留项目名、阶段、保存状态和当前主动作。次要导出、高级辅助进入次级区；模型、Skill 等关键选项可收起，但当前选择保留摘要。导演助手继续辅助修改，结果先预览再应用。

导航使用“未填写 / 已有内容 / 待复核”等真实状态。当前 stageDone 依据正文非空或镜头数量，不能用它暗示用户已经审定。本轮改正呈现语义，沿用已有确认动作与 reviewRequired，不引入审批数据库或全项目内容哈希引擎。

### 2、故事与剧本：编辑内容居中，下一步输入明确

故事页左侧紧凑候选列表，右侧正文。点击候选只预览，“设为当前故事”才替换当前正文，明显提示“预览中，当前编辑仍保留”。预览候选时可以“采用并生成剧本”，不能让按钮读到未展示的旧故事。

保留另存故事、TXT/MD 导入、手工编辑、Skill 和生成结果预览。剧本页突出正文、分镜 Skill 和“用当前剧本生成分镜”；重新生成、历史版本、辅助修改为次级。已有剧本/分镜在新候选生成期间保留，应用结果时说明替换范围。

切阶段、预览和开关助手不能丢未保存编辑。沿用当前保存、恢复和真实 409 冲突规则；保存失败时相关提交操作停下并给出原因，不顺带重写自动保存体系。

### 3、分镜：总览紧凑，复杂编辑按镜头展开

默认摘要行：选择框｜编号/场景｜画面缩略图｜动作/台词摘要｜时长｜素材状态｜编辑/生成。角色、场景、道具和站位图显示缩略图、数量或缺项，不堆叠四层编辑区。无台词镜头不保留大块空台词框。

点击“编辑”在行下展开详情，默认展开一个镜头，可固定另一个比较。详情沿用现有台词、资产引用、提示词、模型及上传/生成控件，按“内容与声音 / 画面参考 / 生成设置”分组。高频字段易达，诊断记录和供应商 ID 收在详情。

图片点击只预览，复选框只批选，编辑按钮只展开。按钮明确写“生成视频”，删除收进“更多”；已有素材时显示播放/替换。保留原表格视图与字段编辑能力，不靠删功能简化。

验收目标：1440×900、100% 缩放、未展开详情时至少看到 4 条完整摘要行；1366×768 不遮挡主按钮；摘要可截断，全文编辑不可截断；50 镜头下滚动、选择和任务回填不跳行。

### 4、资产与任务：说明“生成给谁、正在用哪个”

字段统一为“生成参考图”“当前使用图片”；操作用“从资产中心添加”“收藏到资产中心”，按真实可见范围说明，不能称为全平台公共库。名称单行、描述多行；保留三视图默认/显式选择、清图防回显、原生选图和目录窗口。

素材准备明确为可选：无角色/道具的镜头不报缺项；模型允许文生视频时没有图片也可提交；模型要求首帧才显示具体阻塞和补齐入口。站位图解释为该镜头构图辅助，避免被误认为全片必须生成的资产。

任务用“项目名 · 镜头 03 视频 / 角色名三视图”命名，结果缩略图或音频播放器优先，模型与提示词折叠。任务成功与当前使用分开：mediaId 等于目标当前引用时显示“当前使用”；否则“可查看/替换”，不把后来被替换的结果误标成从未处理。

目标明确时提供“返回镜头 03”“查看并采用”；目标删除、来源缺失时如实显示。保留豆包现有自动回填行为：自动回填显示“已回填，可替换”，手动采用场景显示“待选择”。不为统一卡片新增全局人工审批或自动重试机制。

### 5、预览与导出：保留能力，纠正预期

限制播放器高度，使镜头条、配音/BGM 和关键状态首屏可见；缺失项列镜头编号并可直达。导出按“去剪映继续剪辑 / 下载素材与字幕 / 备份项目”组织，说明各项包含什么、在哪里完成最终成片。

本轮不新增内置 MP4 编码器、云渲染和完整剪辑器，也不新增最终成片计数。原有配音、BGM、剪映草稿、项目 JSON、字幕、剪辑包全部保留，文案如实表达现有能力。

## 三、调整 VS 重做：按相同范围重新估算

A 调整：在现有页面、回调、状态和 API 上改变布局、操作层级、文案与交互，必要时抽出摘要展示组件。B 重做：创作界面与前端编排重新搭建，保留相同后端、授权、模型、插件及非创作模块。两者交付同样的交互和功能。

| 同范围工作项 | A 调整（人日） | B 重做（人日） | 差异依据 |
|---|---:|---:|---|
| 流程核对、关键原型与复用验证 | 1 | 1 | 同样需要明确交互和验收 |
| 导航、工具栏与主次操作 | 0.5 | 2 | 调整沿用阶段与入口；重做重接外壳 |
| 创意、候选故事与剧本编辑 | 2 | 4 | 数量、预览、选用、导入、编辑及确认已存在 |
| 分镜总览与展开编辑 | 3 | 6 | 调整保留回调/编辑区；重做重建镜头交互 |
| 资产与图片交互 | 1 | 2 | 调整复用弹窗、目录、清图规则 |
| 任务结果卡与对象定位 | 1.5 | 3 | 沿用任务查询/恢复，只改展示及采用识别 |
| 预览布局与导出组织 | 0.5 | 2 | 执行能力不变；重做需重接音轨/预览/导出 |
| 回归、双主题、双端验证与交接 | 2.5 | 6 | 重做接线更广，需要更广的功能等价验证 |
| **合计** | **12** | **26** | **96 / 208 小时；1 人日=8 小时有效工程工作** |

节省率 `(26−12)/26≈53.8%`。按用户规则，节省率 ≥50% 选择调整，因此当前选择 **A**。以 B=26 为基准，A≤13 人日才达门槛，当前余量只有 1 人日；表内半天只是工作包粒度，不代表工时预测精确到半天。

源码依据：CreativeWorkspace 已有 storyVersionCount、候选预览、人工正文、导入和确认生成；StoryboardRows 已通过 onEdit/onGenerate/onUpload/onManageAssets 连接生产能力，适合增设摘要；GenerationDialog 已有请求 ID、提交锁；当前任务监控及豆包恢复可以继续使用。这些支持“可复用”的判断，不是工时实测。

估算置信度中低，暂给 ±25% 规划区间：A 约 9–15、B 约 20–33 人日，不能保证所有情况下都满足 50% 门槛。P0 限时半天验证一个真实分镜“折叠→展开→编辑→保存”，剩余半天核对原型与修订估算；若改造复杂度上升，按同一公式重新选。12/26 替代此前扩大范围的 41/50，不能混用。若重做指授权、模型、数据库和插件全部归零，本表不适用，也没有必要为 UI 改造这样做。

## 四、优先级、顺序和验收

| 顺序 | 优先级 | 交付内容 | 人日 | 通过条件 |
|---|---|---|---:|---|
| 第1步 | P0 | 功能对照、分镜复用验证、关键原型、重算工时 | 1 | 复用有证据；两条路线同范围比较 |
| 第2步 | P1 | 分镜紧凑总览＋单镜头展开 | 3 | 首屏≥4行；编辑/批选/预览独立；原功能保留 |
| 第3步 | P1 | 资产可选分支＋任务结果展示/返回对象 | 2.5 | 直接视频可走通；参考与当前图片清楚；采用状态真实 |
| 第4步 | P1 | 创意—候选故事—剧本的操作层级与输入版本 | 2 | X可调；导入可跳过；预览不覆盖；下游用当前正文 |
| 第5步 | P2 | 导航/工具栏、预览/导出、文案与基础视觉 | 1 | 当前主动作清楚；缺项直达；导出如实表达 |
| 第6步 | 必须 | 回归、双主题/尺寸、双端验证、交接 | 2.5 | 保存/生成/回填不退化；未实测平台明确标注 |
| **合计** | | | **12** | |

先做分镜，因为它承载最重复的编辑/生成，且本次截图已有明确问题证据。故事/剧本有源码依据但上一轮未完整实看，P0 要补走，不能把建议都说成已验证缺陷。导航换皮后置。

验收旅程：①idea→X个候选→选择手改→剧本手改→分镜→直接视频；②导入故事→剧本→分镜→复用/生成资产→按需站位图→视频；③已有分镜/视频→只修改指定镜头，原结果保留，其他镜头不变。先用模拟响应和已有合法素材，真实模型调用单独约定次数与额度。

必须守住：保存期间编辑不丢、预览不覆盖、真实409保留、sourceMetadata不丢、任务身份不变、清图不回显、账号不串数据、原生窗口保留、旧表格/配音/经营/管理员功能可达。UI重排不改数据库，不迁移真实用户数据，不覆盖运行中的安装版。

## 五、设计依据与边界

采用 ui-ux-pro-max 的渐进展示、标签清晰、状态保留、错误就地反馈与键盘可达原则；保留深浅主题、中文系统字体和现有图标。正文建议14–16px；通过移走重复栏和折叠次要信息获得空间，不靠微型字挤密度；状态同时以文字表达。

该 skill 两次 design-system 查询返回营销落地页布局，不适用本工作台，未采用其 Hero、字体/色板与滚动动效建议。本案依据业务流程、实看审查和源码复用条件。渐进展示参考 [NN/g](https://www.nngroup.com/articles/progressive-disclosure/)，状态保留参考 [React 官方文档](https://react.dev/learn/preserving-and-resetting-state)；这些来源不证明本项目工时估算。

本轮仅形成方案和实施清单，没有修改业务源码、付费生成、打包或发布。内置成片渲染、自动批次编排、精确依赖失效引擎可另立需求，不作为本次 UI 调整的前提。

低保真交互原型：[评审入口](../../prototypes/workflow-ui-adjustment/index.html)、[使用与验证说明](../../prototypes/workflow-ui-adjustment/README.md)。原型已独立实现，不代表上述正式系统调整已完成。
